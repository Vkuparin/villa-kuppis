T2 review (villa-kuppis-f23-t2-review-001, 2026-10-19) returned four findings, all fixed in 2aba669: (P1) a command exception escaped the worker and stopped all later commands — the worker now fails only that one command and keeps processing (test_command_error_does_not_kill_worker); (P2) quick restarts left interrupted commands pending until the 120s orphan window — start() now fails every pending event, since the in-memory queue never survives a restart (fail_orphaned_pending; restart test tightened from 121s to 5s); (P2) a concurrent same-unit request that lost the pending-slot race could get a misleading 503 instead of 409 (test_concurrent_same_unit_one_409); (P2) POST to unknown paths answered 405 — do_POST now mirrors do_GET routing: 405 for known paths with the wrong method, JSON 404 for unknown API paths (test_post_unknown_path_404). Full suite 189 tests OK. Re-verification (villa-kuppis-f23-t2-review-002) confirmed those fixes and flagged one remaining window: submit() and the 409 re-check were separate steps, so a slot clearing between them could still read as a shutdown — fixed in 6628b46: submit() now returns the refusal reason atomically under the reservation lock ("pending"/"stopped"/None) and request() acts on the reason without re-checking; a new deterministic test pins both arms (busy refusal surviving slot clearing → 409, stopped → 503). Note: the coordinator's 002 request text misdescribed the 405/404 fix as a UI event-display change and cited two tests that were never written (coordinator error, corrected here); the reviewer's sandbox suite run errors are expected there (read-only sandbox, no writable temp dir for the tests) — the coordinator's local runs are the verification evidence. Re-verification 003 (villa-kuppis-f23-t2-review-003) approved the fix within the two-file scope, no new findings (2026-10-19).
