T2 review (villa-kuppis-f23-t2-review-001, 2026-10-19) returned two findings, both fixed in 2aba669: (P2) a concurrent same-unit request that lost the pending-slot race could get a misleading 503 "shutting down" instead of 409 — `request()` now checks the pending slot after a failed submit and returns 409; 503 is reserved for a genuinely stopped gateway, covered by a new shutdown test plus a two-thread race test asserting exactly one 202 and one 409. (P3) rejected commands were invisible in the web UI's event list because the `pending` filter hid failed results — failed commands now render as a red row with the failure reason, covered by an app test.
